## 직접 확인

최신 백엔드에 `python manage.py migrate` 후 앱과 연결한다.

1. **BE-12·7:** 집과 다른 목적지로 일정 추가 → 경로 고르기. 수단별 후보와 기본 최단 선택을 확인한다. 선택 카드와 도보·자전거 지도 미리보기에 서버 안내 문장이 보인다. 자동차 4종 확대는 BE-8로 남아 있다.
2. **BE-16:** 일정의 알람 근거 → 지각 위험. 정보가 부족하면 이유가 나오며, 준비 시간 범위 등 변동성 근거가 있으면 안전·보통·도박을 고를 수 있다. 하나를 선택하고 계속하기 → 알람 근거와 예약 시각이 바뀌고 재진입 후에도 유지된다. 시험의 τ .99처럼 프리셋 밖 값은 직접 고르기 전까지 유지된다.
3. **BE-18:** 일정 추가 → 출발지를 검색한 장소로, 도착지를 집으로 선택 → 저장. 집 설정을 다른 주소로 바꾼 뒤 일정에 다시 들어가면 새 집이 목적지가 된다. 출발지와 집이 50m 미만이면 서버 오류를 해당 입력 아래 표시한다.

분포는 **모형으로 계산한 예상 비율**이다. 실측 횟수·최근 30일 통계로 표시하지 않는다. 위험 옵션은 기존 알람 계산기를 공유하며 GET 요청이 외부 경로를 다시 조회하지 않는다.

## 재현 가능한 자동 검증

API 34+ 에뮬레이터, 시간대 Asia/Seoul, 백엔드 가상환경·Android SDK/JDK가 필요하다.

```bash
# 저장소 루트; 외부 응답만 재생하고 실제 앱·백엔드·기기 알람을 사용한다.
backend/.venv/bin/python qa/demo/run.py --replay-routing --no-video --device emulator-5554

# 기능 전용 API 회귀; 외부 키를 비우는 독립 테스트 설정을 사용한다.
backend/.venv/bin/python -m pytest -c backend/pytest.ini \
  backend/apps/routing/tests/test_candidate_contract.py \
  backend/apps/events/tests/test_risk_options.py \
  backend/apps/events/tests/test_home_destination.py -q
```

E2E는 실제 UI 가입·설정·일정 생성 후 경로 안내, 리스크 빈 상태 → 모형 옵션 → 선택 저장·기기 예약, 집 목적지 생성 → 프로필 변경을 확인한다. 이후 실제 알람 → 루틴 → GPS 출발·즉시 도착 → 관측·리포트까지 이어 간다.

리스크의 양쪽 상태를 재현하기 위해 **일회용 로컬 DB에만** 블록 선택과 이동 변동성 입력을 준비한다. 옵션 응답·계산 결과는 실제 API가 만든다. 집 목적지는 별도 Place 행이 생기지 않는지도 검사한다. 검증 후 입력을 복원하고 같은 일정으로 이동 E2E를 이어 간다.

외부 지도·경로는 기록된 도보와 고정 대중교통·집 변경 사례를 재생한다. 실시간 카카오·공용 배포 검증은 별도다. 공용 DB를 수정하지 않는다.
