## F-6. ⑤ 리스크 선택 (`1:53`) + ⑤-a 선택지 준비 중 — 신규 (x 420, y 3520)

⑤-a(서버가 옵션을 주지 않을 때, 지금 실제로 보이는 화면):
1. "‹ 지각 위험" / "얼마나 안전하게 갈까?" / "시각을 정하지 말고, 감수할 지각 위험을 정하면 됨".
2. 카드 "지금 적용된 값 · τ 0.90" / "7:32 AM" / "τ 출처 · 수업 일정 기본값".
3. 카드 "● 선택지 준비 중"(Amber 점) / "안전·보통·도박 중에서 고르는 기능은 서버 계산이 붙으면 열림. 지금은 위에 적힌 τ 로 계산함". (τ 출처는 2번 카드의 "τ 출처 · …" 가 말한다. 종류 없는 일정은 "기본값".)
4. 카드 "열리면 고를 수 있는 것" / 안전 · 보통 · 도박 세 줄(설명 문구는 지금 코드와 같음).

- 지도가 들어간 시안은 **실제 데이터**로 다시 만들었다. 서버 후보 응답(카카오) → 앱과 같은 맞춤(360×260 요청 단위, 여백 18) → 마커 없는 정적 지도(scale 2) → EPSG:5181 로 투영한 경로선. 프레임 1px 이 요청 단위 1 이라 선이 지도 그림의 도로·역 위에 그대로 놓인다.

## 왜 고쳤나

- 경로선이 지도 가운데에서 **두 배 멀리** 그려졌다. 신림역 → 서울대 301동 미리보기의 끝이 관악산 비탈에 찍혔다. 축척 `2^(lv-4)` m/요청 단위가 틀렸고 실측은 `2^(lv-3)` 이다. 예전 측정은 마커를 넣은 지도로 했는데, 카카오는 마커가 다 보이게 줌·중심을 바꾼다.
- 좌표 변환을 카카오 지도 좌표계(EPSG:5181 TM)로 바꿨다. 카카오 좌표 변환 API 의 `WTM` 과 일곱 지점에서 1mm 안으로 맞는다. 예전 근사(위도 1° = 111,320m, 지도 북쪽 = 진북)는 부산에서 4.8km 떨어진 점이 약 100m 어긋났다.
- 같은 변환을 쓰는 곳이 함께 맞는다. 경로 미리보기, 일정 지도와 이동 중 지도, ⑰ 지도에서 고르기의 핀·끌기·"이 지역 재검색"이다.

## ④-a 이동 중 경로 지도

앱은 이동 중에 출발지 기준 선을 버린다. 현재 위치에서 1분마다 다시 받은 경로 **하나**를 보라 실선(4.5)으로 그리고, 지도도 그 선에 맞춘다(`withLiveRouteDisplay`, `applyLiveRoute`). 시안은 이와 달랐다.

- 지운 것: 지나온 구간(파랑), 남은 구간(어두운 선), 대안 줄("여기서부터 9호선 · 3분 빠름" + 선 견본), "출발함" · "도착" 태그. 앱이 그리지 않는 것들이다.
- 선은 보라 4.5 하나다. 출발 표식은 그 선의 시작(현재 위치 옆), 도착 표식은 끝이다. 내 위치 점을 맨 위에 둔다.
- 요약 줄: "여기서부터 641 → 2호선 · 2분 빠름"(보라 12 Medium) · "6.0km 이동"(파랑 12 Bold).
- 예시는 실제 조회값이다. 2호선 신림 → 강남(10.0km · 20분)에서 6.0km 간 지점(사당과 방배 사이)으로 `resolve_route` 를 부르면 2호선 16분, 641 → 2호선 14분이 온다. 옛 예시 위치(4.6km)에서는 더 빠른 길이 없었다.
- 노트에서 "움직인 거리가 적으면 건너뜀" 을 뺐다. 지금 코드에는 거리 조건이 없고 1분 간격만 있다(`LiveRouteDecision`).
- 프레임 높이 430 → 418. 라벨 `164:29` 를 따라 올렸다.
- 남은 차이: 현재 위치 버튼이 시안은 34, 앱은 48dp 다. 지도 정확도와 관계없어 그대로 두었다.
