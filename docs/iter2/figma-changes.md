## F-0. Design System — 변수 컬렉션 `transit` 추가

구간 막대·노선 칩·타임라인 점의 색을 변수로 둔다. 값은 앱 `SegmentPalette.kt` 와 같다(같은 PR 규칙).

지하철 노선색은 `transit/subway/<권역>/<노선>`(예 `transit/subway/seoul/2` `#00A84D`)으로 `SegmentPalette` 의 서울·부산·대구·대전·광주 표를 그대로 옮긴다.

## F-1. ⑬-c 도보 (`249:101`)

- 후보 카드 3장 → **1장**. 18분 카드만 남기고 22분·25분 카드 삭제.
- 남은 카드: "18분 도보" · 배지(서버 문구, 예 "걸어갈 수 있는 거리") · 요약 한 줄 "1.2km · 1,600걸음 · 60kcal (거리 기반 추정)"(TextSecondary 11). 빠르기 진행 막대 삭제(10-05 결정).
- "● 추천 경로 안내 / … 계단 1개, 경사 1곳" 블록 삭제(계단·경사 제외 결정, 안내 문장 API 없음).
- 카드 맨 아래 오른쪽 "지도로 보기 ›"(Accent, 12 Bold). 선택 상태 = 주황 테두리 2.
- 상태 변형 "좌표 없음": "지도로 보기" 대신 카드 아래 "지도 미리보기를 받지 못했음"(TextSecondary 10).

## F-2. ⑬-d 자전거 (`249:165`)

## F-3. ⑬-e 경로 지도 — 신규 (x 2440, y 1840, 360×800)

⑰ 지도에서 고르기(`151:2`)와 ④-a(`164:2`)의 지도 요소를 재사용한다.
1. 헤더 "‹ 경로 지도"(TextSecondary 14 Bold).
2. 제목 행 "18분"(24 Bold) + "도보"(13 TextSecondary), 오른쪽 배지 칩.
3. 부제 "신림역 → 서울대학교 관악캠퍼스"(13 TextSecondary).
4. 지도(남은 높이 전부, radius `radius/card`): 서버 정적 지도 PNG 배경, 경로선 `color/track` 4, 출발 = 흰 속·어두운 테두리, 도착 = 어두운 속·흰 테두리, 왼쪽 위 "⤢ 경로 전체 보기" 알약, 왼쪽 아래 카카오 CI. **현재 위치 버튼 없음**, 캡션 "경로" 없음.
5. 요약: 도보 "1.2km · 1,600걸음 · 60kcal (거리 기반 추정)", 자전거는 F-2 지표 칸 2개.
6. 기본 버튼 "이 경로로 계산".

상태 변형: 지도 불러오는 중(가운데 스피너), 지도 오류(가운데 서버 메시지, 알약으로 다시 시도), 자전거.

## F-4. ⑬-b 전체 옵션 (`232:265`)

- 구간 막대 칸·노선 칩·타임라인 점의 채움을 F-0 변수로 바인딩. 글자는 지금처럼 `transit/on-vehicle`(도보는 `transit/on-neutral`).
- 대체 버스 칩: 대표 칩 옆에 최대 4개, 넘치면 "+N"(TextSecondary 9 Bold). 각 칩은 자기 버스 종류색.
- "이동 시간만 실측값" 같은 출처 안내 상자가 남아 있으면 삭제(코드는 `804bb43` 에서 제거됨, 노드 `77:51` 삭제 기록 있음).

## F-5. ⑫ 일정 추가 (`80:2`) · ⑬-a' 출발·도착 지정 (`144:4`) · ⑬ 오류 상태

- 도착지 행 바로 아래 오류 한 줄 변형: 빨강 `color/red` 11, 문구는 서버 메시지 그대로 "출발지와 도착지는 50m 이상 떨어져 있어야 한다.". 출발지 행에도 같은 자리의 변형(국외 좌표 등). 이때 화면 맨 아래 공통 오류 줄은 비어 있음.
- ⑬ 경로 선택 오류 블록 변형(새 노드, ⑬-a `77:2` 아래 빈 칸): 빨간 점 + "경로를 불러오지 못했음" / 서버 메시지 / 링크 "출발지·도착지 다시 고르기"(Accent 12 Bold). 일반 오류 변형은 링크가 "눌러서 다시 시도".

## F-6. ⑤ 리스크 선택 (`1:53`) + ⑤-a 선택지 준비 중 — 신규 (x 420, y 3520)

`1:53`(선택지가 있을 때):
- 옵션 카드의 확률이 없을 때 변형: 확률 글자와 확률 막대를 **둘 다 숨김**("학습 중" 없음).
- 출처 안내 상자("이동 시간만 실측값" 류)가 있으면 삭제.

⑤-a(서버가 옵션을 주지 않을 때, 지금 실제로 보이는 화면):
1. "‹ 지각 위험" / "얼마나 안전하게 갈까?" / "시각을 정하지 말고, 감수할 지각 위험을 정하면 됨".
2. 카드 "지금 적용된 값 · τ 0.90" / "7:32 AM" / "τ 출처 · 수업 일정 기본값".
3. 카드 "● 선택지 준비 중"(Amber 점) / "안전·보통·도박 중에서 고르는 기능은 서버 계산이 붙으면 열림. 지금은 위에 적힌 τ 로 계산함". (τ 출처는 2번 카드의 "τ 출처 · …" 가 말한다. 종류 없는 일정은 "기본값".)
4. 카드 "열리면 고를 수 있는 것" / 안전 · 보통 · 도박 세 줄(설명 문구는 지금 코드와 같음).
5. 카드 "● 지금도 자동으로 적용되는 것" / "시험·발표·기차 일정은 τ 를 높게 잡아 더 여유 있게 계산함. 일정 종류만 골라 두면 알아서 반영됨".
- **넣지 않는 것**: "실제 출발·도착 기록 0일 / 14일" 진행 줄, "며칠 쓰면…" 문장, "평균이 아니라 분포를…" 문장.

## F-7. ④ 알람 결정 (`1:2`)

- 확률 없음 변형: "● 정시 도착 확률 · 아직 계산할 수 없음"(TextSecondary 13) / 이유 "이동 시간은 경로 조회값 하나뿐임"(10) / "→ 이동 기록이 쌓이면 변동성이 생김"(Accent 10). "학습 중" 문구 삭제.
- 계산 방법 카드의 이동 줄 설명: "카카오 경로 추정 · 2호선 → 5513 · …", 보정 변형 "카카오 추정 · 전체 이동 기록으로 보정 · …". "실측" 삭제.
- τ 줄: "적용 τ 0.90 · 수업 일정 기본값"(종류 없음 변형 "· 기본값").
- 블록 입구(블록 없음): 본문 "준비 시간이 한 덩어리라 왜 그 값인지 설명할 수 없음. 항목으로 쪼개고 최소~최대 범위를 주면 준비 시간 변동이 계산에 반영됨".
