# BE-20 / 주간 반복 일정

`back-iter2`에서 기존 일정/알람을 재사용한다. 월~일을 고르면 선택한 날짜 이후 해당 요일마다 독립 일정이 생긴다.

## 동작과 API

- `POST /api/events`에 `repeat_weekdays: [0, 2]`를 보내면 월/수 반복이다(0=월, 6=일). 생략/빈 배열은 기존 단일 일정이다. 중복 요일은 정리하고 범위 밖 값은 400이다.
- 선택한 날짜부터 처음 일치하는 요일이 첫 일정이다. 반복 시작 시각은 현재 이후여야 한다. 생성 응답은 기존 일정 형식을 유지하며 `recurrence_id`, `recurrence_date`, `repeat_weekdays`를 추가한다.
- 반복 규칙은 생성 당시 프로필 시간대를 보존한다. **오늘 00:00 이상 / 7일 뒤 00:00 미만**의 회차만 자동 생성/알람 계산한다. 날짜별 알람은 기존 하루 첫 알람 규칙을 따른다.
- 첫 시작이 더 먼 미래여도 규칙과 기준 일정은 저장한다. 기준 일정의 알람은 `null`이며 7일 범위에 들어올 때 계산/목록 표시한다.
- `GET /api/events`가 필요한 회차를 보충한다. 앱의 기존 목록 새로고침/백그라운드 동기화를 재사용한다. 이미 있는 회차는 재생성/재계산하지 않으며 자동 보충은 수동 ON/OFF를 초기화하지 않는다.
- 기존 `PATCH /api/events/{id}`는 **그 회차만** 바꾼다. 시각을 옮겨도 원래 반복 날짜를 보존하며 새 날짜가 범위에 들어오면 빠진 알람을 계산한다.
- 기존 `DELETE /api/events/{id}`는 그 회차를 삭제하고 원래 날짜를 예외로 남긴다. 다시 조회해도 되살아나지 않는다. 과거 반복 기록은 DB/리포트/상세 조회에 유지하며 현재 반복 목록에서 제외해 최신 일정이 페이지 뒤로 밀리지 않게 한다.

반복 규칙과 날짜별 회차는 같은 트랜잭션으로 저장한다. 규칙 행 잠금과 `(recurrence, recurrence_date)` 유일성 제약으로 중복 생성/삭제 재생성을 막는다. `events.0008_weekly_recurrence`가 필요하며, 기존 일정의 새 필드는 DB 기본값 `NULL`로 구버전 INSERT를 허용한다.

서버/마이그레이션을 먼저 배포한 뒤 새 앱을 사용한다. 이전 서버는 `repeat_weekdays`를 무시하고 단일 일정으로 저장할 수 있다.

이번 범위는 주간 요일 반복과 회차별 관리다. 반복 전체의 규칙 수정/종료 UI는 포함하지 않는다.

## 직접 확인

1. 최신 서버/앱에서 일정 추가 → 날짜는 내일/시간은 오전 9시 → 내일과 모레에 해당하는 두 요일 선택 → 목적지 설정 후 저장한다. 홈에 두 회차가 나타나야 한다.
2. 두 회차를 ON으로 설정한 뒤 하나만 OFF 한다. 재진입 후 그 회차만 OFF이고 다른 회차는 ON을 유지해야 한다.
3. 한 회차를 열고 화면 맨 아래의 일정 삭제 → 새로고침한다. 해당 날짜만 사라지고 다른 회차는 유지돼야 한다.
