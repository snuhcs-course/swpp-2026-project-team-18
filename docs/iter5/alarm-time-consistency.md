# 홈 알람·보통 추천·기기 예약 시각 일치 검증

2026-11-28 · `front-iter5` · Android QA `0.18.0` / versionCode 19

홈에서 실제 예약한 알람과 ‘시각 바꾸기’의 ‘보통·추천’ 시각이 달랐다. 화면의 숫자를 맞춰 덮어쓰지 않고 실제 Django API와 QA 앱에서 원인을 재현하고 수정 전후를 비교했다. 기본 배치는 유지하고 조회 중·실패의 버튼 상태와 재시도는 Figma에서 먼저 보완했다.

## 실제로 재현한 조건

- API 36 `SWPP_APP` 에뮬레이터의 별도 앱 `com.swpp.wakeup.qa`를 사용했다. 개인 앱·실제 계정·운영 DB에 접근하지 않았다.
- 현재 Django 뷰·직렬화·계획 계산을 새 일회용 SQLite DB에서 실행했다. 외부 경로·지도 응답만 기존 QA replay를 사용했고, 알람 시각·확률·API 응답·기기 예약 결과를 주입하지 않았다.
- 기본 목표 0.9, 준비 루틴 신고 범위 20~40분, 대중교통 원값 20분·잔차 표준편차 8분으로 내일 오전 9시 일정을 만들었다. 처음에는 저장된 알람과 보통 추천이 모두 오전 7:53이었다.
- 일반 `POST /api/routines/observations/batch`로 과거 60분 준비 기록 8개를 업로드했다. 이 기록이 준비 추정에 즉시 반영되는 동안 저장된 미래 계획이 갱신되지 않는 상태가 생겼다.
- 재현 계정은 격리된 DB에서 학습을 실행하기 위한 합성 입력이다. N26이 제외하는 운영 QA 접두를 사용하면 학습 자체가 제외되므로 이 경우를 재현할 수 없다. 해당 계정과 DB를 베타·운영 데이터에 복사하지 않는다.

## 수정 범위와 검증

새 준비 블록 관측이 저장되면 저장된 경로 원값으로 미래 알람을 다시 계산한다. GPS 출발과 알람 해제 기록이 서로 다른 순서로 업로드되어 준비 표본이 완성되는 경우도 같은 경계를 사용한다. 중복·초기화로 제외된 기록과 이미 울렸거나 출발한 일정은 기존 규칙을 따른다. 직접 정한 시각과 확인한 알람의 변경 제안도 보존한다. 새 외부 경로 API 호출은 추가하지 않았다.

앱은 캐시된 상세 계획이 있어도 시트를 열거나 재시도할 때 온라인 계획을 다시 읽는다. 상세 화면의 오프라인 열람은 유지하되 시트의 엄격한 조회는 실패 시 캐시를 최신 값으로 승인하지 않는다. 계획·선택지·홈과 기기 알람 동기화가 끝나야 저장·복원이 활성화된다. 조회 중·실패 상태는 [Figma 설계](https://www.figma.com/design/FoiB0Q7bTIjUsjhiQLefJQ?node-id=736-3051)를 먼저 반영했다.

읽기 전에는 대기 관측 업로드를 기다리고 큐가 비었는지 확인한다. 작업자·서비스·화면이 만든 큐 인스턴스가 공통 업로드 경계를 사용한다. 전송 중 새로 쌓인 기록과 계정 전환 뒤의 기록은 지우지 않는다. 홈에서 관측이 새로 수신되면 갱신된 목록을 한 번 다시 받아 기기 알람에 적용하며 업로드 재귀 호출은 하지 않는다.

### 캐시된 상세와 미전송 기록의 실제 기기 회귀

같은 기기 테스트가 상세 화면을 열어 기존 오전 7:34 계획을 메모리에 둔 뒤, 실제 PATCH API로 일정 시작을 오전 9시에서 10시로 바꿨다. 과거 준비 기록 1건을 앱의 실제 전송 큐에 넣은 뒤 시트를 열었다. 업로드 API의 201 수신과 대기 0건을 확인했고, 시트·홈·기기 알람이 모두 오전 8:34로 바뀌었다. 이 추가 기록은 모델의 이상치 처리 대상일 수 있으므로 학습 효과의 수치 평가로 해석하지 않는다.

## 재현과 운영 반영

[재현 도구 안내](../../qa/alarm-time/README.md)에 일회용 DB 생성, 서버 실행, QA APK 설치·권한·설정 전달·기기 테스트 명령을 적었다. `qa/alarm-time/run.py --seed --run-id <새 이름>`은 초기 일치와 관측 업로드 후 비교를 저장한다. 서버는 별도의 `--serve` 명령으로 `127.0.0.1`에만 연다. 공용 서버 모드는 없다.

운영 반영에는 **서버 수정 선행 배포와 앱 업데이트가 모두 필요**하다. 이미 오래된 상태로 저장된 계획이 배포만으로 일괄 교정되는 것은 아니다. 기존 재계산 또는 새 관측 수신에 의한 갱신과 앱 재조회·기기 알람 동기화를 확인해야 한다. 이 작업에서 운영 서버 배포나 실제 사용자 일괄 재계산은 실행하지 않았다.

공유한 증거에는 합성 화면 PNG와 시각·차이만 있는 JSON을 넣었다. 로그인 자격 증명, 서버 서명 키, DB, 전체 로그와 XML은 공유 증거에 포함하지 않았다. 비공개 설정과 원본 DB는 Git에서 제외된 `.artifacts` 안에 둔다.
