입구는 내 정보 탭의 `약속방`이다. 채팅·약속 시간 옮기기·멤버 상세는 구현 범위에서 제외했다.

**아래는 앱이 구현한 제안 계약이며 서버 구현·합의·배포가 끝난 계약이 아니다.**
기준 소스 `c3ea88f`에 `rooms` 서버 앱은 없다. 실제 서버가 지원하지 않으면 앱은
`약속방을 아직 쓸 수 없어요`와 다시 시도를 표시한다. 가짜 방·알람·성공 상태를 만들지 않는다.

## 공통

- 기존 `ApiClient`의 인증·토큰 갱신·서버 주소를 사용한다. 모두 로그인 필수다.
- 모든 시각은 시간대 오프셋을 포함하는 ISO 8601 문자열이다. 앱은 기기 시간대로 표시한다.
- 성공한 쓰기는 완전한 방 상세를 반환한다. 앱이 내 일정을 다시 조회해 새 개인 알람을 등록한다.
- 오류는 기존 `{"error":{"code":"...","message":"...","details":{...}}}` 형식이다.
- 다른 방 멤버의 접근은 `404`다. 권한·확률 분배·탐욕 선택·개인 Event 생성은 서버 책임이다.
- 멤버에게 공유하는 것은 닉네임, 기상 시각, 그 시각을 앞당길 제안뿐이다. 멤버 집 좌표·집 주소·경로·이메일·개인 Event 내용은 응답에 넣지 않는다.

## API

| 요청 | 성공 | 앱 사용 |
| --- | --- | --- |
| `GET /api/rooms/` | `200 {"results":[방 요약, ...]}` | 내가 참가한 방 목록. 빈 목록도 `results: []` 필수 |
| `POST /api/rooms/` | `201 방 상세` 또는 같은 `client_uuid`의 `200 방 상세` | 방·약속 한 개·개설자 멤버십·개인 Event 생성 |
| `POST /api/rooms/join/` | `200 방 상세` | 초대 코드 참가. 이미 멤버여도 중복 Event를 만들지 않고 같은 방 반환 |
| `GET /api/rooms/{id}/` | `200 방 상세` | 멤버 알람과 기상 시각 조정 제안 새로고침 |

방 요약:

```json
{
  "id": 12,
  "title": "금요일 모임",
  "start_at": "2026-12-04T09:00:00+09:00",
  "destination_name": "서울대입구역",
  "group_target_probability": 0.9,
  "member_count": 2
}
```

방 상세는 요약의 모든 필드와 다음 필드를 함께 반환한다:

```json
{
  "invite_code": "ABC123",
  "members": [
    {"nickname":"김진호","is_me":true,"alarm_at":"2026-12-04T07:10:00+09:00","earlier_minutes":0},
    {"nickname":"박준하","is_me":false,"alarm_at":"2026-12-04T06:55:00+09:00","earlier_minutes":5}
  ],
  "wake_suggestion": {
    "nickname":"박준하",
    "earlier_minutes":5
  }
}
```

- `members` 길이는 `member_count`와 같고 `is_me: true`는 정확히 한 명이다.
- `invite_code`는 대문자 영문·숫자 6자리다. 초대 코드는 방 멤버에게만 반환한다.
- `alarm_at: null`은 아직 계산 결과가 없다는 뜻이다. 앱은 `아직 계산 중이에요`로 표시한다.
- `earlier_minutes: null`은 조정 결과가 아직 없다는 뜻, `0`은 유지, 양수는 서버의 앞당김 제안이다.
- `wake_suggestion: null`을 허용한다. 제안이 있으면 닉네임·분이 해당 멤버의 값과 일치해야 한다.
- 조정 안내는 공개된 닉네임·분으로 앱이 표시한다. 집 주소·경로가 섞일 수 있는
  자유 형식 멤버 설명은 읽지 않는다. 이 안내는 확률·추천 대상·분을 새로 계산하지 않는다.
- 멤버 닉네임이 같을 수 있어 목록의 고유성 판정에는 닉네임을 쓰지 않는다.

방 생성 본문:

```json
{
  "title":"금요일 모임",
  "start_at":"2026-12-04T09:00:00+09:00",
  "destination":{
    "name":"서울대입구역",
    "address":"서울 관악구 남부순환로 1822",
    "lat":37.4813,
    "lng":126.9527,
    "kakao_place_id":"선택한 검색 결과의 ID 또는 null"
  },
  "group_target_probability":0.9,
  "client_uuid":"새 생성 시도별 UUID"
}
```

- 앱은 방 이름 1~40자, 미래 약속 시각, 검색 결과에서 선택한 장소, 목표 1~99%를 검사한다.
  서버도 최종 검증한다. 장소 검색은 기존 `GET /api/places/search`를 사용하며 `near`/현재 위치를 보내지 않는다.
- 본문의 장소 좌표는 사용자가 선택한 목적지다. 휴대폰이 측정한 GPS 좌표가 아니다.
- `client_uuid`는 응답 유실 뒤 같은 입력을 재전송할 때 유지한다. 사용자+UUID로 중복 생성을 막아야 한다.
- 개설·참가 시 각자의 프로필 집·준비 시간 및 서버 경로로 **개인 Event**를 만든다.
  프로필이 부족하거나 경로 생성에 실패하면 서버가 이유와 다음 행동을 반환한다.

참가 본문은 `{"code":"ABC123"}`다.

## 오류 및 서버 협업 사항

| 상황 | 권장 응답 / 앱 처리 |
| --- | --- |
| 방 목록·생성 URL 자체 미지원 | `404` 또는 `405`: 준비 중 안내, 새로고침. 빈 목록·생성 성공으로 처리하지 않음 |
| 명시적 기능 미지원 | `501` 또는 `error.code: "rooms_unavailable"`: 같은 안내 |
| 코드가 없거나 방 접근 불가 | join/detail의 `404`: 코드·참가 여부 확인, 입력 유지. 미지원으로 오인하지 않음 |
| 입력 오류 | `400`, `details.title`, `destination`, `start_at`, `group_target_probability`, `code`를 해당 칸 아래 표시 |
| 프로필 미완성 | 예: `409 profile_incomplete` + 집·준비 시간 설정 안내. 거짓 참가 성공 금지 |
| 한도·마감·참가 불가 | `409` + 해요체 이유·다음 행동 |
| 과다 요청 | `429` + 다시 시도 안내 |
| 권한·세션 만료 | `401`: 다시 로그인 안내. 다른 멤버의 데이터 사본 숨김 |
| 통신·5xx·형식 오류 | 이유와 다시 시도. 폼 입력과 생성 UUID 유지 |

BE에게 필요한 작업: `rooms` 모델·라우팅·권한, 중복 요청 처리, 개인 Event 생성, 멤버 수 변경 시 재계산,
AT-22의 `그룹 목표^(1/n)`, AT-23의 서버 탐욕 선택, 공개 필드 제한. 클라이언트는 이 계산을 대신하지 않는다.

## 검증 범위

- JVM: DTO 필드 매핑·누락·개인정보 경계·404 구분, 생성/참가의 성공·실패·재시도,
  입력 검증·중복 제출·오래된 검색 결과 무시·권한 상실 시 상세 지우기.
- 기기 테스트 소스 `RoomsScreenTest`: 목록의 방 보기부터 멤버 기상 시각·조정 안내 표시까지.
- 실제 서버 방 생성·참가·알람 등록과 기기 테스트 **실행은 서버 구현 및 연결 기기 확보 뒤 확인해야 한다**.
  빌드·단위 테스트 통과만으로 그룹 기능의 E2E 완료를 주장하지 않는다.
