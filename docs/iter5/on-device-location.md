# Iteration 5: 측위 좌표의 온디바이스 처리

Figma 변경: [I5 작업 화면](https://www.figma.com/design/FoiB0Q7bTIjUsjhiQLefJQ?node-id=711-2500), 이동 지도 `711:2809`.

## 앱 변경

- 출발·도착 관측은 종류, 판정·진입 시각, 거리, 정확도, 체류, 멱등 키만 업로드한다. `TripObservationInput.lat/lng`는 이전 호출부와 소스 호환을 위한 `transient` 필드이며 JSON으로 읽거나 쓰지 않는다.
- 이전 버전의 오프라인 큐를 읽을 때도 좌표를 무시하고 좌표 없는 JSON으로 디스크를 갱신한다. 새 관측의 생성·적재 때도 좌표를 담지 않는다.
- 추적 서비스의 이동 중·출발 전 `routes/live` 호출과 타이머를 제거했다. 저장소의 기존 `liveRoute` 진입점도 네트워크 호출 없이 빈 결과를 돌려준다.
- 이전 버전의 현재 위치 경로는 추적 복구 시 지우며 지도에 다시 적용하지 않는다. 출발·도착·이탈·진행률 판정은 기존대로 기기에서 수행한다.
- 출발지의 ‘현재 위치’ 선택을 제거했다. 선택한 집 또는 장소 검색으로 출발지를 정한다. 이전 화면 콜백을 호출해도 GPS·역지오코딩 요청을 하지 않는다.
- 장소·캘린더 장소 검색의 가까운 순 기준은 선택한 출발지 또는 저장한 집이다. 측위 좌표를 `near`로 보내지 않는다. 지도 영역 재검색은 사용자가 선택한 지도 영역을 기준으로 한다.
- 지도 요청의 중심·범위는 검색 결과, 선택한 출발지·집·경로와 사용자의 지도 조작으로만 정한다. GPS 마커는 앱에서 겹쳐 그리며 지도 중심이나 서버 마커로 보내지 않는다. 현재 위치로 지도 이동 버튼은 제거하고 경로 전체 보기를 유지했다.

## 배포 전 BE 필수 작업

**서버를 앱보다 먼저 또는 동시에 배포해야 한다.** 현재 서버의 GPS 관측 `obs_gps_has_location` 제약과 쓰기 검증은 좌표를 요구한다. 서버 변경 없이 이 앱을 배포하면 GPS 관측 업로드가 400으로 거절될 수 있다.

BE에서 좌표 없는 GPS 관측을 허용하고 좌표 입력을 받지 않도록 수정하며, 저장된 `TripObservation.lat/lng`를 지우는 마이그레이션이 필요하다. 이번 FE 작업에서는 서버나 운영 데이터를 변경하지 않았다.

PM은 원스토어 기준과 개인정보 처리방침을 확인하고 이동 중 대안 경로·출발 전 경로 확인에 관한 AT 범위를 수정해야 한다. 사용자가 직접 선택한 출발지·도착지 좌표는 경로 계산을 위해 계속 서버에 보낸다.

## 검증 범위

- `TripObservationsTest`: GPS 관측·이전 큐·기존 호출자의 좌표가 직렬화되지 않고 시각·거리·정확도·체류가 유지됨.
- `ObservationQueuesTest`: 이전 큐의 좌표를 디스크와 재전송에서 제거하고 관측을 정상 처리함.
- `ManualArrivalTest`: 최근 위치가 있어도 수동 도착 좌표는 제외하며 거리를 기기에서 계산함.
- `EventRepositoryTest`: 이동 중과 출발 전 경로 확인이 API를 호출하지 않음.
- `RouteMapLiveAvailabilityTest`: 이전 현재 위치 경로가 지도 경로·서버 요청용 카메라를 바꾸지 않고 로컬 마커는 보존됨.

실기기 패킷 확인, 권한·위치 추적, 7일 알람·배터리 측정은 별도의 기기 검증이 필요하다. 이 문서는 해당 측정을 완료했다는 근거가 아니다.
