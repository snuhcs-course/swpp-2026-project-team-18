## 김진호

### 완료한 작업

- 일정표 Iteration 5의 44개 작업을 코드·디자인·실제 검증과 대조했어요. [작업별 이행표](schedule-frontend-status.md)에 FE 구현 범위와 외부에서 필요한 일을 분리했어요. 원본 일정표의 시간·상태·회의 참석은 임의로 채우지 않았어요.
- [Figma 선행 설계](https://www.figma.com/design/FoiB0Q7bTIjUsjhiQLefJQ?node-id=724-2847) 후 홈·경로·알람 확인·일정 수정의 주요 동작을 스크롤 밖에 고정하고 홈의 아침 루틴 입구를 추가했어요. 큰 글자의 수치 상자는 별도의 세로 배치로 읽을 수 있게 했어요.
- 설정 하위 화면과 처음 안내 다시 보기가 실제 진입 화면으로 돌아가게 했어요. 계정별 `HomeNavigation`으로 탐색을 분리하고 로그아웃 뒤 늦은 응답이 화면을 다시 열지 못하게 했어요.
- 빠른 선택은 서버가 준 값 중 구별되는 시각만 표시해요. 같은 시각이더라도 원래 선택한 단계와 직접 지정 의도를 보존하고, 늦게 도착한 계획이 사용자 입력을 지우지 않게 했어요. 다른 일정에는 이전 편집이 따라가지 않아요.
- 기본 추천 복원 시 이전에 직접 고른 위험 단계도 해제하도록 서버 의존성을 수정했어요. 저장된 경로로 재계산하고 불가능하면 변경을 롤백해요.
- 이동 진행·도착·지도·경로 순서는 알람 상세에서 확인해요. 이동 탭은 해당 일정으로 연결하며 같은 진행 화면을 중복해서 그리지 않아요. 준비·이동·여유는 실제 수치와 측정/고정 출처가 있는 상자로 정리했어요.
- 앱과 알림의 직접 도착 모두 위치 상태를 안내하고 확인을 받은 뒤 기록해요. 일정 시작 시각 경과·기록 창 만료를 도착 완료와 구분했어요. 위치 신선도·정확도·거리는 기기에서만 판단해요.
- 좌표 없는 관측, 예전 큐 좌표 정리, live 호출 차단, 선택한 출발지 기준 검색을 유지했어요. 서버도 구버전 좌표를 저장하지 않고 기존 관측 좌표만 지우는 `observations.0008`을 준비했어요. 집·선택 목적지·출발지는 지우지 않아요.
- 도움말·문장·짧은 라벨, 알람 근거·확률 미상 이유·미확인 알람·AI 요약 라벨, 알림 꺼짐 배너와 집 이름 변경을 반영했어요. 설정·계정·리포트·아침 기록의 작은 설명과 48dp 동작 영역·의미 역할도 보완했어요.
- 최신 일정표 P42의 그룹 제외에 맞춰 약속방 앱 진입을 제거했어요. 이전 제안 코드·Figma는 보관 상태로 구분했어요.
- 수동 AppContainer·저장소 인터페이스와 Trip/AlarmDecision/EventEditor/Me ViewModel 분리를 유지하고 탐색·직접 도착 규칙을 독립 테스트 경계로 옮겼어요. [구조 설명](frontend-architecture.md)에 책임과 남은 Home 연결부를 명시했어요.
- S-4 일별 집계·CSV·버전/사용자 필터·p50/p95·오류율·QA 학습 제외를 구현했고, 이번 서버 의존성까지 회귀 검증했어요. [집계 실행 안내](telemetry-daily.md)를 남겼어요.
- 서명 APK `0.18.0` / versionCode 19와 [설치 안내](release-install.md), 빈 알람·배터리 양식·분석기, 10개 인간 평가 입력 양식을 준비했어요. 실제 실행 수치·캡처·커버리지·서명은 [최신 검증 기록](schedule-frontend-verification.md)에 있어요.

### 남은 작업

- 운영 서버에 이 브랜치의 마이그레이션과 추천 복원 수정이 먼저 적용되어야 해요. `observations.0008`의 과거 관측 좌표 삭제는 역방향 복원이 불가능해요. 서버를 먼저 배포한 뒤 앱의 실제 업로드를 확인해야 해요.
- 실기기에서 개발 도구 없이 설치→가입→집 설정→첫 알람까지의 검증과 일곱 번의 아침·24시간 배터리 비교가 남아요. 자동 테스트나 에뮬레이터를 이 실측 결과로 기록하지 않았어요.
- Android Accessibility Scanner 5화면, 실제 TalkBack 탐색, UAT 2차 사용자 피드백 확인과 주간 요약 10건의 인간 평가가 남아요. 준비한 양식에는 실제 결과만 채워야 해요.
- 베타 시작 전 S-6 사용자·주별 정시율·미룸·준비/이동 MAE 집계가 BE 후속 작업으로 남아요. 12월 12~13일에는 S-4의 베타 기간 CSV를 보관해야 해요.
- `wake_late` 실제 원인 판정, 요금 반영 경로 추천·자동차 다중 경로, 열린 이동의 서버 일일 처리 등은 일정표의 BE 작업이에요. 목적지 밖에서 확인한 직접 도착의 보고서 포함 규칙도 BE·PM 합의가 필요해요.

### 도움 요청

- **BE/배포 담당:** 서버 선행 배포와 마이그레이션 검토·적용, `train_models --users --verbosity 0` 전체 재학습, 실제 업로드·추천 복원 확인이 필요해요. 이번 작업에서 운영 DB를 변경하지 않았어요.
- **PM/팀:** 원스토어 기준·처리방침·요구사항/AT 개정, 그룹 제외 이력, 목적지 밖 직접 도착 정책, 실제 UAT 자료와 인간 평가·실기기 참여가 필요해요. 7일 측정 일정은 원래 12/1 마감과 조율해야 해요.
