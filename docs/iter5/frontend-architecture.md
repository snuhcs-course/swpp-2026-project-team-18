# Iteration 5 프론트엔드 구조

이번 변경은 수동 `AppContainer`를 사용한다. 앱이 이미 생성자 주입을 쓰는 저장소와 테스트용 API 인터페이스를 갖고 있어, Hilt 플러그인·생성 코드를 추가하지 않고 의존성 생성과 수명을 모을 수 있다.

`JitApplication.container`는 앱 전체의 `TokenStore`를 소유한다. `HomeViewModel`을 만들 때 `homeRepositories()`가 그때 로그인한 이메일로 `OfflineCache`의 소유자를 고정하고 새 저장소 묶음을 만든다. 다음 로그인에서 이전 계정 저장소를 재사용하지 않는다.

| 역할 | 현재 소유자 | 테스트 경계 |
| --- | --- | --- |
| 앱 진입·탭 이동·홈 목록 | `HomeViewModel` | 기존 순수 규칙·초기화 순서 검사 |
| 이동 탭 계획·정류장 조회·재시도·취소 | `TripViewModel` | `TripPlanRepository`, `CheckpointCache` 가짜 주입 |
| 알람 시각 시트·빠른 선택·직접 정하기·추천 복원 | `AlarmDecisionViewModel` | `AlarmDecisionRepository`, 기존 계획·저장 후 동기화 함수 주입 |
| 일정 편집의 종류 목록·추가·이름 변경·삭제와 최근 도착지 | `EventEditorViewModel` | `EventEditorRepository`, 폼 식별자·선택·갱신 hook 주입 |
| 비밀번호 변경·이메일 인증·로그인 연결 | `MeViewModel` | `MeRepository`, 시계·화면·계정 갱신 hook 주입 |
| 경로 변경 알림 | `EventTripPlanRepository.changes` | 계정 화면 수명의 `SharedFlow` |
| 로그아웃 전체·학습 기록 초기화·문의·최근 도착지 통신 | `AccountActionsRepository` | `AuthApi`, `SupportApi`, `RouteHistoryApi`, dispatcher 주입 |
| 주간 리포트 주 이동 | 기존 `ReportWeekNavigator` | 조회 함수 주입 |

`HomeViewModel.onRouteChanged()`는 성공한 경로 변경을 저장소의 `changes` 흐름에 알린다. `TripViewModel`은 이를 구독해서 보던 계획을 맞추고 예전 정류장 캐시를 버린다. 저장소를 거치지 않는 화면 사이의 직접 상태 복사를 줄인다. 변경 알림은 디스크나 다음 로그인에 남기지 않는다.

이동 계획과 정류장은 각각 요청 세대 번호를 검사한다. 같은 일정·같은 버전으로 강제 새로고침해도 늦게 끝난 옛 응답이 새 값을 덮지 못한다. 정류장 요청 도중 경로가 바뀌면 옛 구간이 캐시에 다시 저장되는 것도 막는다. 로그아웃과 `onCleared()`는 하위 scope를 취소하고 화면 상태를 비운다. 계정 통신 저장소는 `CancellationException`을 실패 메시지로 바꾸지 않고 전달한다.

`TripViewModelTest`는 요청 중복, 버전 변경, 실패 시 기존 계획 보존, 취소를 무시하고 늦게 끝나는 응답, 오프라인 정류장 사본·명시적 재시도, 경로 변경 알림, 로그아웃 이후 차단을 실행한다. `AccountActionsRepositoryTest`는 상태 코드·본문 전달, 통신 실패, 문의 제한, 취소 전파를 실행한다. 테스트 실행 결과와 실제 계층별 커버리지는 별도 검증 기록을 따른다.

`AlarmDecisionViewModel`은 시트 수명과 선택지 요청의 세대 번호를 따로 둔다. 선택지 재시도로 아직 도착하지 않은 계획 응답이 무효화되는 일을 막는다. 저장 성공 뒤에는 홈·기기 알람 동기화 함수를 호출하고, 동기화 실패는 시트를 열어 둔 채 이유로 표시한다. 저장 중 시트를 닫아도 이미 저장된 알람은 동기화하고 옛 시트의 완료 메시지는 띄우지 않는다. 로그아웃하면 이 동기화도 중단한다. 테스트는 서버가 내려준 실제 τ 전달, 이전 날짜의 야간 알람, 변경 전 시각으로 되돌리기, 구버전·지난 시작 시각 보호, 실패·재시도·취소 경계를 실행한다.

같은 일정의 저장 요청은 시트를 닫았다가 다시 열어도 하나씩 처리한다. 예전 저장 응답이 나중 선택의 계획을 덮는 것을 막는다. 홈 동기화 응답이 다른 새 요청에 밀려 실제 반영되지 않았다면 저장 완료로 닫지 않고 재시도 상태를 유지한다. 계획 조회 실패는 이유를 표시하고 선택지의 재시도로 계획도 다시 받는다.

`EventEditorViewModel`은 종류 목록·생성·이름 변경·삭제와 최근 도착지 요청을 소유한다. 목록 조회와 변경이 겹치면 변경 전에 시작한 목록은 무효화하고, 폼이 바뀐 뒤 완료한 생성 요청이 새 일정의 선택을 바꾸지 않게 폼 식별자를 확인한다. 최근 도착지는 마지막 요청만 반영하며 실패하면 기존 칩을 보존한다. 로그아웃은 요청을 취소하고 응답 세대와 콜백을 무효화한다. `EventEditorViewModelTest`는 이 경계와 서버 오류·입력 보존·중복 전송·취소를 실행한다. `HomeViewModel`의 공개 메서드와 `TagAddState`·`TagEditState` 타입은 UI 호환성을 위해 유지하고 실제 상태·작업은 편집 ViewModel에 위임한다.

분리는 진행 중이다. 알람 상세·제안, 일정 입력 폼·경로 선택, 내 정보·설정의 상태 일부는 아직 `HomeViewModel`에 있다. 이동·시트 상태 타입 위치도 UI 호환성을 위해 당장은 유지했다. 실제 책임을 이전한 범위는 위 표와 같다. 전체 다섯 영역의 완전한 분리와 커버리지 목표 달성은 구분한다. 최종 JVM 보고서에서 ViewModel은 32.8%, Platform은 43.1%로 두 30% 목표를 충족했다. [검증 기록](frontend-verification.md)을 참고한다.


## 2026-11-28 일정표 반영

`HomeNavigation`이 계정 수명의 화면 스택·탭·도움말·안내 종료를 소유한다. 설정 하위 화면과 안내 다시 보기는 실제 진입 화면으로 돌아가며, 다른 탭에 머무는 동안 비동기 저장이 끝나도 저장하던 화면만 닫는다. 로그아웃과 ViewModel 종료는 탐색 세션을 끝내 늦은 콜백의 재진입을 막는다. HomeViewModel의 공개 메서드는 UI 호환성을 위해 유지한다.

`EventCompletion`은 도착·건너뜀·열림·도착 미확인 만료를 구분한다. 일정 시작 시각이 지났다는 이유만으로 도착이라고 하지 않는다. `ManualArrivalReviewController`가 도착 확인 요청·취소·확인 시 재검증·계정 종료를 다루며, `ManualArrivalReview`는 위치 신선도·정확도·목적지 거리의 하한을 기기에서만 판정한다. UI에는 좌표 없는 FAR/NEAR/UNKNOWN만 전달한다. 알림도 바로 기록하지 않고 MainActivity의 해당 일정 조회와 확인 화면으로 연결한다.

알람 시각 시트의 편집 상태는 시작 시각이 아니라 일정 ID에 묶는다. 사용자가 만지지 않은 휠은 늦게 도착한 계획으로 초기화하지만, 명시적으로 고른 값·원래 위험 단계·직접 지정 의도는 보존한다. 다른 일정으로 바뀌면 편집 상태를 초기화한다. 빠른 선택은 서버가 준 시각을 그대로 사용하며, 시간 차이가 작은 후보를 묶어도 숨겨진 현재 선택을 다른 위험 단계로 바꿔 저장하지 않는다.

최신 일정표에서 그룹 기능은 제외되어 내 정보의 약속방 진입을 제거했다. 기존 제안 코드·계약 문서는 보관 기록이며 이번 배포 기능으로 표시하지 않는다. 상세 이행 범위와 최종 수치는 [일정표 이행표](schedule-frontend-status.md)와 [현재 검증](schedule-frontend-verification.md)을 따른다. 11월 27일의 커버리지 수치는 해당 시점의 이력이다.
