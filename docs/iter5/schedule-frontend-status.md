## 완료의 뜻과 도착 직접 기록

일정 시작 시각이 지났다는 사실은 도착 증거가 아니다. GPS 또는 확인한 직접 도착 기록이 있을 때만 도착 완료다. 시작 뒤 한 시간의 기록 창이 끝나면 도착 미확인 상태로 만료하며, 이를 정시 도착으로 바꾸지 않는다.

직접 기록은 GPS 판정과 별도 `detector=manual`로 저장한다. 신선한 위치와 정확도를 고려해 목적지 100m 밖이라고 확실하게 판단되는 경우 경고한다. 오래된 위치·정확도 부족·목적지 없음은 위치 미확인으로 안내한다. 좌표 계산은 기기에서만 수행하고 측위 좌표를 전송하지 않는다. 알림의 도착 동작도 앱의 확인 화면을 거친다.

목적지 밖에서 사용자가 확인한 직접 도착을 학습·정시율에 포함하는 규칙은 기존 서버 정책을 유지했다. 별도의 원인 필드나 자동 제외를 임의로 만들지 않았다. 이 정책은 BE·PM이 확정해야 한다.

## 인간 평가와 실제 측정

[10개 인간 평가 양식](evidence/weekly-summary-human-ratings.csv)은 기존 고정 평가 세트에서 `human_rating=true`로 지정하고 LLM 실행을 허용한 10개 ID만 담는다. 실행 불가 케이스로 평가 수를 채우지 않는다. 실제 LLM 실행 출력·평가자 A/B 점수·사실 오류·의견은 비워 두었다. 서로의 점수를 보기 전에 1~5점으로 채우고, 평균 목표 4.0 이상과 사실 오류를 함께 검토한다. 점수만 맞추기 위해 케이스나 출력을 바꾸지 않는다. 프롬프트 버전·모델·실행 커밋은 실제 실행 기록과 함께 남긴다.

[설치와 실기기 절차](release-install.md), [빈 알람·배터리 양식](evidence/alarms.csv), [분석기](../../APP/scripts/analyze_alarm_evidence.py)를 사용한다. 빈 표를 측정 성공으로 간주하지 않는다. 실제 기기 7일·TalkBack·Scanner·UAT·베타 참여 결과는 자동 테스트로 대체하지 않는다.

## AI 협업과 구현 결정

- 원본 일정표의 ID와 행 번호를 먼저 고정하고 기존 구현·Figma와 대조했다. 문서의 완료 표시를 코드 검증으로 대신 믿지 않았다.
- 독립적인 작업을 빠른 선택·화면 폼·화면 이동·도착 확인·관측 서버 계약으로 나눴으며, 공유 파일 변경과 Gradle 실행은 조정했다.
- 화면 변경은 기존 색·간격 변수와 Noto Sans KR 스타일·버튼 인스턴스로 편집 가능한 Figma를 만든 뒤 Compose로 구현했다. 전체 화면 이미지를 구현 자산으로 쓰지 않았다.
- 시간·확률을 프론트엔드에서 새로 만들어 선택지를 늘리지 않았다. 기존 서버 값의 구별 가능성과 사용자가 실제 선택한 의도를 보존했다.
- 서버 변경은 프론트엔드 계약을 실제로 동작시키는 의존성과 추천 복원 오류 수정에 한정했다. 운영 DB를 읽거나 지우는 작업은 실행하지 않았다.
- 개인 앱 대신 읽기 전용 에뮬레이터의 별도 QA 패키지와 가짜 저장소를 사용한다. 테스트 계정·개인정보·서명 키를 소스나 검증 산출물에 추가하지 않는다.
- 인간 평가·시간 경과가 필요한 측정·서비스 심사·운영 배포를 AI가 완료한 것처럼 기록하지 않는다.

전체 테스트·서명·캡처 결과는 [최신 검증 기록](schedule-frontend-verification.md)을 따른다.
