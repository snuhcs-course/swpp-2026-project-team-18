## 1. 요청

```
POST /api/support/inquiries
Authorization: Bearer <access>

{
  "message": "알람이 예상보다 30분 일찍 울렸어요",
  "reply_email": "me@snu.ac.kr",
  "app_version": "0.21.0",
  "device": "samsung SM-S911N · Android 14"
}
```

| 필드 | 규칙 |
| --- | --- |
| `message` | 필수. 앞뒤 공백을 뺀 10~1000자(앱이 먼저 막는다. 서버도 같은 기준으로 검사) |
| `reply_email` | 필수. 이메일 형식. 로그인 이메일과 달라도 된다(이메일을 주지 않은 소셜 계정이 있다) |
| `app_version` | 선택. 문자열 32자까지 |
| `device` | 선택. 문자열 120자까지. 기기 id 같은 개인 식별 값은 보내지 않는다 |

경로는 제안이다. 다른 경로가 낫다면 앱의 `SupportApi` 한 줄만 바꾼다.

## 2. 서버가 할 일

- 문의를 저장한다(사용자 · 글 · 답 받을 이메일 · 앱 버전 · 기기 · 받은 시각 · 처리 상태). 관리자 화면(Django admin)에서 볼 수 있게.
- **팀에 알린다.** 팀 메일(또는 메신저 웹훅)로 문의 내용을 보낸다. 받을 주소는 환경 변수로 — **어디로 받을지는 팀이 정해야 한다**(지금 정해진 연락처가 없다).
- 사용자에게 접수 확인 메일을 보낼지는 선택(이메일 인증 때 쓰는 메일 발송을 그대로 쓸 수 있다).
- 남용 방지: 사용자당 시간당 5건 정도. 넘으면 429.

## 3. 응답

```
201 Created
{"id": 123}
```

| 상태 | 앱의 안내 |
| --- | --- |
| 2xx | 시트를 닫고 "문의를 보냈어요. 답은 이메일로 보내 드릴게요" |
| 404 · 405 · 501 | "아직 앱에서 문의를 받을 수 없어요. 적은 내용은 그대로 두었어요"(시트는 열린 채) |
| 429 | "문의를 너무 자주 보냈어요. 잠시 후 다시 보내 주세요" |
| 그 밖 · 5xx | "문의를 보내지 못했어요. 잠시 후 다시 시도해 주세요" |
| 연결 실패 | "서버에 연결되지 않아 문의를 보내지 못했어요" |

400 의 필드별 문구(`details.message` · `details.reply_email`)는 앱이 아직 칸 아래에 붙이지 않는다(같은 규칙을 앱이
먼저 검사한다).

## 4. 백엔드 · 팀에 묻는 것

- 문의를 받을 주소(팀 메일 등).
- 로그인하지 않은 사용자의 문의도 받을지. 지금 앱은 도움말이 로그인 뒤에만 열려서 Bearer 를 붙인다.
- 문의에 사용자의 최근 알람 계획 · 로그를 붙여 보낼지(원인 파악에는 좋지만 개인 정보라 동의 문구가 필요).
