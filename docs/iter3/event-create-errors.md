# 일정 추가가 실패할 때 (11-04 피드백)

피드백: "일정 추가 안될 때 에러 났을 때 서버에서 처리 / User에게 저장이 안되는 걸 오류 정보 보여주기 / 오류 났을 때 기존 정보 남아있으면 좋을 듯".
서버 쪽은 0.20.0 에서 처리했다(1~3절). 앱이 할 일은 4절과 [task.md](../../task.md) "프론트 할 일 (11-04)".
구현: `backend/apps/events/views.py` `EventListCreateView`, `backend/apps/common/errors.py`, `planning.services.mark_failed`, 마이그레이션 `events 0014` · 테스트: `backend/apps/events/tests/test_create_errors.py`

## 1. 응답 정리 (`POST /api/events`)

| 상황 | 응답 | 일정 저장 |
| --- | --- | --- |
| 정상 | 201, 일정 + `alarm_plan.status == "ok"` | 됨 |
| 카카오 경로 조회 실패, 출발·도착이 너무 가까워짐 등 | 201, `alarm_plan.status == "route_failed"` | 됨 |
| **알람 계산이 예상하지 못한 오류로 터짐(새로 바뀜)** | 201, `alarm_plan.status == "route_failed"`. 전에는 500 이고 일정이 사라졌다 | 됨 |
| 같은 `client_request_id` 로 다시 보냄(새로 생김) | **200**, 처음 만든 일정 그대로 | 이미 됨 |
| 입력 오류(제목 비었음, 남의 종류, 서비스 지역 밖, 출발·도착 같음 등) | 400 `invalid`, `details` 에 필드별 문구 | 안 됨 |
| 로그인 만료 | 401 | 안 됨 |
| 그 밖의 서버 오류(새로 바뀜) | 500 `server_error` + 한국어 `message`. 전에는 HTML 500 이라 코드·문구가 없었다 | 안 됨 |

모든 오류 본문은 `{"error": {"code", "message", "details"}}` 다. 500 도 이제 같다(배포 설정, `DEBUG` 가 꺼져 있을 때). 스택트레이스는 서버 로그에 남는다.

## 2. 다시 보내도 한 번만 만든다 (`client_request_id`)

응답을 못 받았다고 해서 저장이 안 된 것은 아니다. Render 가 잠에서 깨는 동안이나 느린 망에서 앱이 시간 초과로 포기해도 서버는 일정을 만들 수 있다. 그때 사용자가 다시 누르면 같은 일정이 두 개 생긴다.

- 생성 본문에 선택 항목 `client_request_id` 를 받는다. 영문·숫자·`-`·`_` 8~64자. UUID 를 쓰면 된다.
- 같은 사용자가 같은 값으로 다시 보내면 검증·경로 조회 없이 **처음 만든 일정을 200 으로** 돌려준다. 본문이 달라도 그렇다(고칠 것은 `PATCH`).
- 400 으로 실패한 요청은 아무것도 저장하지 않으므로 같은 값으로 고쳐 다시 보내면 만든다.
- 사용자마다 따로 센다. 수정(`PATCH`)에 실려 와도 무시한다. 응답에는 싣지 않는다.
- 보내지 않으면 전과 같다(구버전 앱).

## 3. 알람 계산이 터져도 일정은 남는다

한 번 일정은 저장한 뒤 알람을 계산한다. 계산 중 예상하지 못한 오류가 나면 계산만 되돌리고 계획을 `route_failed` 로 둔다. 사용자는 입력을 다시 하지 않고 알람 결정 화면의 다시 계산(`POST /api/events/{id}/recompute`)을 누르면 된다.

반복 일정은 전처럼 통째로 되돌린다(500 `server_error`, 아무것도 저장 안 됨). 회차를 펼치다 터진 규칙을 남기면 목록 조회가 같은 규칙을 다시 펼치다 매번 터진다. 앱은 입력을 남겨 두고 다시 시도하게 하면 된다.

## 4. 앱 할 일 (프론트)

지금 앱(`HomeViewModel.submitAdd`)은 실패해도 입력을 지우지 않고, 버튼 위에 빨간 글자 한 줄을 띄운다. 출발지·도착지 오류만 그 칸 아래에 나온다.

1. **오류를 눈에 띄게.** 저장 실패는 스낵바나 대화상자로 알린다. 예: "일정을 저장하지 못했어요. 입력한 내용은 그대로 있어요" + [다시 시도].
   - 400: `error.details` 의 필드별 문구를 그 칸 아래에 보여 준다(제목·시각·종류·경로·출발지·도착지). 칸이 없는 것은 `error.message`.
   - 500 `server_error`·네트워크 오류·시간 초과: 서버 문구나 "잠시 뒤 다시 시도" 안내 + [다시 시도].
   - 401: 다시 로그인으로 보내되 입력은 남긴다(2번).
2. **입력을 남긴다.**
   - 실패하면 지우지 않는다(지금도 그렇다). [다시 시도]는 같은 입력을 같은 `client_request_id` 로 보낸다.
   - 지금은 홈에서 "일정 추가" 를 다시 누르면 `resetAdd()` 가 지운다(`MainActivity` `onAddEventClick`). 저장하지 못한 초안이 있으면 이어서 쓰게 한다(또는 "작성 중인 일정이 있어요. 이어서 쓸까요?"). 저장에 성공했을 때와 사용자가 버렸을 때만 지운다.
   - (선택) 앱이 꺼져도 남게 `SavedStateHandle` 이나 기기 저장소에 초안을 둔다.
3. **중복 방지.** 일정 추가 화면을 새로 열 때 UUID 를 하나 만들어 `AddState` 에 두고 `POST /api/events` 에 `client_request_id` 로 싣는다. 다시 시도할 때는 같은 값, 성공하거나 초안을 버리면 새 값. 200 도 201 과 같이 성공으로 처리한다.
4. **저장은 됐지만 알람이 없는 경우.** 201 인데 `alarm_plan.status == "route_failed"` 이면 "일정을 추가했습니다" 대신 "일정은 저장했어요. 알람을 계산하지 못해 다시 계산이 필요해요" 를 띄우고 알람 결정 화면으로 안내한다.
5. 일정 수정(`PATCH`)도 1·2번을 같은 방식으로 한다(`submitEdit`).
